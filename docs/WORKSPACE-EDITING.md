# Saved workspace editing

PV-CONTEXT-002 adds an editor for saved bot/project/space names and instructions. One named icon beside the active workspace title opens the existing dialog language. Save updates the same row; Cancel leaves it unchanged. ID, kind, linked chats, messages and drafts remain intact. New instructions apply to later sends; an in-flight request keeps its captured instructions.

Rust validates names (nonblank, at most 80 Unicode scalar values) and instructions (at most 8192 UTF-8 bytes). A single parameterized SQLite update compares the opened snapshot's ID/kind/name/instructions before writing. Missing or changed rows fail without overwriting. No schema/version migration. The renderer never updates its saved copy before success; failed saves retain typed text. An explicit Load saved version action replaces the editor only after a successful native read, including when a successful write's reply was lost. Pending save/read disables duplicate submissions and closing.

Verification: focused SQLite reopen/link-isolation/invalid-input/stale-snapshot tests; component save/cancel/error/reload/pending/Unicode tests; actual lab editor capture/reload followed by a synthetic provider request using the changed instructions. Independent read-only data-path/spec review found no material findings. Subsequent small dismissal/focus refinements were source-inspected, not independently re-reviewed. All app checks/builds/UI remain CI/lab only. No credential/provider/tool changes.

Rollback removes editor/native update/read entry points, leaving the existing schema and saved values compatible with prior builds. Values can be restored through a new guarded edit; a failed SQL update is atomic and leaves the old row. Existing closed-database backup/restore checks remain applicable. Code rollback does not pretend to undo successful user edits.

Implementation is authored; formatting/diff/link inspection only locally. SQLite/component/native fixture checks and changed-surface captures await CI/lab. New exports: native-workspace-edit.png (narrow editor) and native-workspace-conflict.png. The fixture creates its own bot/SQLite profile, simulates a second native writer after the editor opens, checks rejected overwrite and retained draft, reloads explicitly, then verifies saved identity/linked chats/reload and the next two actual synthetic provider requests. No real model/auth use or new UI/native acceptance claimed. This is one cohesive data/native/UI/verification slice; its size reflects independent failure boundaries, not multiple unrelated features.
