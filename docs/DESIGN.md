# Pavane desktop design

The accepted composition is **R3-B / Open Canvas — Deep Charcoal**, selected by Dylan on 31 October 2026 and explicitly authorized for implementation. [Reference and contract](OPEN-CANVAS.md). It supersedes the earlier three-column sketch and visible rail/sidebar. Keep the established shadcn/Radix interaction primitives; the retired web Fractal theme remains superseded.

The composition is a full-window conversation canvas with a bottom composer. A labelled Chats button opens a modal navigation drawer with history, workspaces and Connections. There is no persistent rail or sidebar. Chat, Projects, Spaces and Bots are the working destinations. Unimplemented media routes and disabled attachment controls stay out of everyday navigation; future work remains in TASKS.md. Dark neutral surfaces, fine separators, restrained radii and system typography keep the working content primary.

All color roles live in `src/tokens.css`; colors use OKLCH and support a future light mode through `light-dark`. Spacing uses logical properties, a 4/8px rhythm, and fluid shell widths. There are no downloaded fonts, decorative image assets or continuous effects. Native Windows chrome supplies standard window behavior.

Use icons for recognized actions with accessible names and keyboard-accessible tooltips. Keep visible labels for workflow context, unfamiliar actions such as Delete Soon, model choices, destructive actions and useful errors. Do not hide consequences or connection status behind hover. Menus and dialogs use Radix focus, escape and focus-return behavior; unimplemented capabilities stay out of everyday controls.

The composer accepts Enter to send and Shift+Enter for a newline, preserving IME composition. Escape during composition belongs to the input method; ordinary Escape in the focused composer stops responses without clearing the draft. Its direct visual reference is T3 Chat, inspected live on 29 October 2026: 16px input at 24px line height, a borderless editor, two-line initial writing space and a distinct control row within one rounded surface. Pavane retains its neutral palette and reference-requested model placement, with a circular send/stop action. Focus belongs to the outer composer; never draw a second rounded input box inside it. Long drafts grow to a bounded scroll area while preserving the toolbar. Ctrl+K opens title search; Ctrl+Shift+O creates a chat. Navigation, search, copy, cancellation, rename, keeping and deletion stay keyboard-reachable. Reduced motion removes the spinner rotation and motion transitions without hiding status text. The same dismissible, keyboard-contained drawer works at desktop and narrow widths; it never shrinks the canvas.

User messages use quiet right-aligned bubbles; assistant replies use the full reading column with a provider/model label. Replies support Markdown, lists, tables and code blocks with copy actions. Raw HTML and remote images are blocked. Links require an explicit user click and open through a native HTTP/HTTPS-only command.

The model picker follows the supplied reference: provider/favourites rail, search, compact model rows, stars and a reasoning/service-tier flyout. Show only capabilities returned by that model's provider. A single click selects a model; comparison is an explicit mode with up to four responses. Arrow keys and Enter navigate the list; Ctrl+D stars a model, ArrowRight opens its options and Ctrl+1–9 selects favourites. Preserve selections across restarts, including an unavailable selection rather than silently sending to another model. No permissions switch is exposed in text chat.

Keep connection and quota claims tied to actual provider data. Unknown limits remain unknown. Attachments, autonomous tools and media generation stay explicitly planned.

Search stays within the active provider/favourites filter. Reopening clears the query and highlights the selected model; keyboard navigation keeps that row visible. ArrowRight opens options only at the end of the search input, preserving text editing and IME composition. Favourite shortcuts choose one model and leave comparison mode. Show any active non-default service tier beside the selected model. Display and submission share the same supported-capability fallback. Selecting a model returns focus to the composer; an asynchronous send must not steal focus from search, dialogs or another chat. Streaming updates preserve table scroll position, and copy feedback describes the text actually copied.

Background model/quota refresh must not block a known model from sending the next message; initial discovery remains guarded. Oversized Unicode text stays intact in the editor with an explicit unsaved warning and disabled send until it fits. Picker search uses a single focus underline, with a visible input outline in forced-colors mode. Markdown headings retain a readable hierarchy within the conversation column.

## Simplicity and recovery — 31 October 2026

Dylan's current simplicity request supersedes earlier duplicated controls and placeholder surfaces. One Connections entry lives in the navigation drawer, with setup also reachable from the model picker and unavailable-model recovery. Its flat provider list exposes one setup panel at a time, preserves unsaved inputs when switching and uses the same fields/buttons throughout. Recheck connections is the sole manual discovery action. Keep model selection/options in the composer picker; preserve meaningful reasoning/tier preferences without a second editor. The modal uses available space and its columns stack when needed.

One current-chat retention notice in the header owns the Keep action. Temporary chat creation discloses 30-day expiry in the drawer creation menu; ordinary chats remain permanent. Avoid repeated header status or Local labels for cloud models. Each workspace has one create action in its header. Failures need a relevant action: Try again preserves unfinished reply/draft and adds a guarded new attempt; Retry save resubmits the cached draft; Recheck connections refreshes availability without sending a message. Use plain error text, retain failed input and show success only after the authoritative operation. Do not expose a Fix control for capabilities the app does not implement. [Scope, references and verification](SIMPLER-PAVANE.md).

## Open Canvas implementation

The drawer starts closed, combines permanent and temporary history into one list, and preserves searchable expiry markers, chat menus and all four working destinations. Ctrl+K opens it directly into search; Escape dismisses it and restores focus. Selecting a chat dismisses it without dropping drafts, and connection setup restores focus to Chats. Workspace name/instruction editing belongs in the chat header. Normal chat has no prompt chips, alpha/profile decoration, breadcrumb, storage footer or printed keyboard instructions. Save state remains available to assistive technology; failed saves keep their visible error and Retry save. Recognizable icon actions keep names/tooltips.

Neutral near-black tokens and restrained charcoal reply/composer cards follow the selected reference. Keep readable body text, visible focus, long Markdown/table scrolling and model comparison. The model picker sits left of send inside the composer. Empty chat centers the heading/composer; existing replies remain a scrolling column above it. No color value is shown to the end user.
