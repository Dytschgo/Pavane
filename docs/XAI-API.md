## Native/API contract

The fixed origin is https://api.x.ai/v1. GET /language-models supplies the authenticating key's language-model catalogue. Include only returned text-input/text-output models; IDs stay opaque, aliases are not guessed, and reasoning choices/defaults come only from returned capability metadata. The endpoint documents no output-token maximum. Bound list bytes/count rather than invent pagination. Discovery is not inference acceptance. [Models reference](https://docs.x.ai/developers/rest-api-reference/inference/models).

POST /responses uses sensitive header-only Bearer authentication, local user/assistant text history, optional workspace instructions, stream=true, store=false and max_output_tokens=4096. No previous_response_id, encrypted-reasoning history, tool definitions, search, automatic continuation, proxy, redirect, retry or account/model fallback is configured. Saving/removal invalidates discovery and only that provider's renderer entries. Native queued runs recheck the exact captured key and supported reasoning selection before sending. [Responses reference](https://docs.x.ai/developers/rest-api-reference/inference/responses), [local-history/storage option](https://docs.x.ai/developers/model-capabilities/text/generate-text).

The output limit bounds visible answer tokens only; it is not a reasoning-token or cost cap. Not carrying encrypted reasoning is a fidelity/performance gap for multi-turn reasoning. Existing 600-second run and 30-second read deadlines are retained, shorter than xAI's recommendation for long reasoning. Stop ends local consumption without guaranteeing remote computation/billing cancellation. Quota and subscription balance remain unknown. [Best practices and limitations](https://docs.x.ai/developers/model-capabilities/text/best-practices).

## Streaming contract

Use typed Responses events, not the older Chat Completion choices/delta shape. The provider's best-practices example establishes output_text.delta and completed/incomplete terminals. The xAI-linked maintained adapter is inspected at [vercel/ai dffe4053c15709577329518044b1ec1d4c6bb0fe](https://github.com/vercel/ai/tree/dffe4053c15709577329518044b1ec1d4c6bb0fe/packages/xai/src/responses); its schemas and recordings also establish response.done compatibility, indexed item/part identity and data-only SSE. The generic REST blurb's [DONE] marker is insufficient semantic success.

Bound UTF-8 lines/events, wire bytes, item/part counts and visible output. Render visible text once; ignore known reasoning/encrypted content, including owner-bound reasoning_text events. Validate IDs/indices and repeated completion snapshots. Require completed status plus a matching final output snapshot or earlier completed item snapshots; tolerate omitted intermediate closers when the final snapshot proves identical text. Multiple visible messages must finish in output order: reject a new message while an earlier message is open rather than append interleaved text in the wrong order. Refusal/unsupported content, tool items, malformed order, contradictory text, incomplete/failed/error, bare [DONE] and EOF preserve partial text and fail. Do not impose undocumented ID prefixes or nonempty reasoning IDs. Claude and xAI share byte framing only; their state/completion parsers remain separate.

The source recordings used for shape inspection are [plain text](https://github.com/vercel/ai/blob/dffe4053c15709577329518044b1ec1d4c6bb0fe/packages/xai/src/responses/__fixtures__/xai-text-streaming.1.chunks.txt), [reasoning](https://github.com/vercel/ai/blob/dffe4053c15709577329518044b1ec1d4c6bb0fe/packages/xai/src/responses/__fixtures__/xai-text-with-reasoning-streaming.1.chunks.txt) and [store=false](https://github.com/vercel/ai/blob/dffe4053c15709577329518044b1ec1d4c6bb0fe/packages/xai/src/responses/__fixtures__/xai-text-with-reasoning-streaming-store-false.1.chunks.txt).
