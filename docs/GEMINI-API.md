## User workflow

Open Connections, get an API key from the linked Google AI Studio page, paste it into the masked Gemini API field and choose Save key. Saving replaces the profile's stored key; discovery then checks model access. A saved key is not a successful model/inference test. Choose a discovered Gemini model in the composer and send explicitly. API usage has its own account limits and may incur charges. Pavane neither buys credits nor starts a login/install flow.

Save failure keeps the masked field available for retry. Invalid format leaves the previous stored value untouched. A syntactically valid replacement is stored before model access is checked; if Google rejects it, re-enter another key or remove it. Remove key is idempotent and affects new requests, retaining the current model selection as unavailable rather than silently choosing another provider. An in-flight response can still finish. Removal does not revoke the key at Google.

## Native credential boundary

`credentials.rs` uses Windows Credential Manager with a fixed Pavane/Gemini/v1 namespace and the canonical native profile-directory path. The renderer cannot choose vault targets. The two Tauri commands save/remove a key; no command returns one. Keys never enter SQLite, browser preferences, URLs, source manifests or logs. Input exists transiently in the masked WebView field and local IPC; native buffers and HTTP headers also hold transient copies. Native owned secret buffers are wiped on drop and Debug output is redacted; no universal memory-erasure claim is made.

Stored values are bounded to 1–2048 ASCII graphic bytes. Replacement uses one CredWriteW call, without deleting the old value first. Reads validate blob bounds/type and release their OS buffer; deletion treats missing values as success. Unsupported platforms and storage failures return explicit errors, with no plaintext fallback. A vault failure disables Gemini rather than preventing existing Codex/Ollama use. Windows-user protection and path-based profile separation are not a sandbox against other code running as that user. SQLite backup/restore does not transfer the key; re-enter it for a moved/restored profile.

## HTTP and response boundary

Production requests use only `https://generativelanguage.googleapis.com/v1beta`. There is no endpoint override or imported CLI authentication. Keys use a sensitive `x-goog-api-key` header, never a query parameter. The client refuses cleartext, redirects, proxies and automatic retries. Discovery is bounded to five pages/200 displayed models, 1 MiB per page and ten seconds overall. Names/IDs are bounded; model IDs cannot insert paths or queries. It conservatively lists Gemini generateContent entries, excluding known media-specific names. Discovery is availability metadata, not proof of entitlement or remaining quota. No made-up usage meter or unsupported reasoning/tier options are returned.

Each cached catalog is bound to the exact native credential and a discovery generation. Replacing/removing a key invalidates its models. An older request cannot clear or publish over a newer one, including external Credential Manager changes. Send captures a native credential for each accepted run before persistence, including duplicate model IDs, and rechecks it when the queued worker starts. A key switch cannot redirect queued content to the replacement account; that run fails instead. Snapshots never enter a renderer DTO or SQLite.

Text-only requests map stored context roles to Google's contents, carry the captured workspace instructions, request one TEXT candidate and register no tools. Streaming handles SSE boundaries, fragmented Unicode and CR/LF variants. Completed events are delivered before a later parse failure, independently of network chunk grouping. Thought text is not displayed. Media, function/code output, wrong content roles, malformed data, blocked/unfinished responses and HTTP errors fail explicitly. Response frames are limited to 256 KiB, wire data to 32 MiB and delivered text to the existing 2 MiB cap. The existing native queue, checkpoints, 600-second turn deadline and biased cancellation retain partial text/drafts. Dropping the HTTP future stops local consumption; it cannot guarantee that Google's remote computation or billing stops.

[Google API authentication](https://ai.google.dev/api), [model listing](https://ai.google.dev/api/models) and [streaming generation](https://ai.google.dev/api/generate-content) support this route. Google controls account access, policy and billing; this implementation makes no live account claim.

## Evidence and remaining acceptance

Fourteen HTTP/decoder/catalog tests, seven Windows-applicable credential tests and a persisted-run credential-assignment regression are authored. They use loopback mock HTTP and disposable credential targets only: header-vs-URL handling, pagination/filtering, HTTPS/redirect refusal, error redaction, text/instruction payloads, partial text followed by malformed data, Unicode/SSE framing, unsupported outputs, incomplete streams, callback failure, output bounds, missing-key/no-network behavior, stale/rekey discovery races and an HTTP cancellation/disconnect. The persisted-run regression covers duplicate Gemini IDs mixed with other providers. Credential checks cover validation, redaction, wiping, reopening, cross-profile separation, replacement, failed-input preservation, deletion and cleanup after panic. Non-Windows storage has an explicit unsupported-platform test instead of Windows tests.

Four form tests, a Gemini picker test and an App removal/selection regression are authored. The native fixture adds a narrow connection capture, observes the fresh profile's native needsKey status, checks masking/invalid input, and exercises removal of that empty profile key. It never saves a valid key or contacts the Gemini API. Thus actual key entry plus live inference is not covered by that fixture; vault/HTTP behavior is exercised in CI, and paid/live account acceptance remains separate. CI41158425657 passed the authored baseline plus the overlapping-read/drop regression; original-boundary stress failed at5a49801. The unchanged workload will exercise the credential-call mutex hypothesis; independent review and native UI acceptance remain pending. Local work was source editing/formatting, documentation and artifact inspection only.

Independent source security/spec review found no credential/command/origin blocker and three response/cache findings: chunk-dependent partial loss, stale discovery clearing a newer cache, and unsupported tool/media output passing as text. Root corrected them and added regressions. A separate review of the new queued-credential boundary found duplicate model IDs lost their second snapshot; root changed assignment to per-model queues and added the persisted-run regression. Follow-up corrections were source-inspected, not independently re-reviewed. Native worker queue/cancel integration is not directly covered; the HTTP cancellation test and unchanged native cancellation path cover their narrower boundaries. The vault author and reviewer made no credential, provider or app calls on this PC.

## Rollback

Remove the new commands, Gemini dispatch/catalog and key form; existing schema, chats, Codex/Ollama and saved preferences remain compatible. Successful key changes are separate Windows state: use Remove key in the same profile or Windows Credential Manager to remove that exact target before rolling code back. No bulk credential cleanup is performed. Backend/API/UI/negative tests stay together because they establish one usable connection and its credential failure boundary; no unrelated provider or dependency upgrade is included.
